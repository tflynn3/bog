# bogctl and standalone deployment

Build `go build ./cmd/bogctl`. Use `bogctl health -addr http://127.0.0.1:8080`, `bogctl ingest < rows.ndjson`, and `bogctl query -start 2025-01-01T00:00:00Z -end 2025-01-02T00:00:00Z`. Query writes NDJSON in server order and follows snapshot cursors. Bounds are inclusive start and exclusive end. Point query requests at one process: a cursor cannot survive process restart or be moved between processes. An invalid continuation stops the command; discard partial output and restart the query if a complete snapshot is needed.

Ingest sends sequential batches of at most 4 MiB. Each request is atomic, but an input stream may span several requests and earlier requests may already be committed when a later one fails. A rejected write is known not to have been admitted or to have been rolled back. A lost response or unexpected response has an unknown outcome: do not automatically retry, because the server does not deduplicate writes. The timeout covers the entire command.

`operator/standalone.yaml` is a single-node starting point, not an HA operator. Choose a pinned image, storage class and capacity, and ensure the data directory is owned by the server user and is not group- or world-writable. The Linux storage must satisfy the durability requirements in the main README, including powersafe overwrite and directory sync; a Kubernetes PVC alone does not establish those guarantees. The startup probe allows WAL replay to finish before readiness is checked. OnDelete upgrades require a maintenance window. Do not increase the replica count: the server has no replication, fencing, leader election or deduplication, and separate replicas contain separate data.

For a consistent offline backup, stop all writers, gracefully stop Bog and wait for process exit, then copy `bog.wal` and `bog.commit` together from the same data directory. Keep their original bytes and restrictive ownership and permissions. Restore both files into a new, empty isolated data directory on compatible Linux storage; start the same compatible Bog version and wait for health. Query expected records and compare against independently recorded expectations before considering the restore verified. Never copy these files independently from a running instance; the marker and WAL can represent different commits. Store and test backups separately from the original volume.

Automated HA, quorum acknowledgments, online snapshots, rolling upgrades without outage, and compatibility-gated reconciliation require server protocols that do not exist in this base. They are not provided by this deployment.
