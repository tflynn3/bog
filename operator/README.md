# Experimental single-member operator

This controller creates one `bog` StatefulSet and a persistent volume claim per member. Set `BOG_IMAGE` to a compatible image containing the Bog binary; optionally set `BOG_STORAGE` and `BOG_STORAGE_CLASS`. It runs in its service account namespace and requires get/create access to StatefulSets. Build `./cmd/bog-operator` in this module into an image, replace the image placeholders in `manifests/operator.yaml`, and apply the manifest in the intended namespace; the manifest also supplies the headless Service. The volume must meet the Linux filesystem, ownership, locking, atomic rename, sync, and powersafe-overwrite requirements in the main Bog README. The image must arrange for `/data` to be writable and privately owned by the Bog process. Kubernetes PVC access mode alone does not establish these guarantees.

Replication and automatic failover are **not implemented**. `BOG_REPLICAS` must be 1; do not manually scale the StatefulSet. The controller refuses to automatically change an existing StatefulSet when the requested configuration hash differs, so upgrades and storage changes require an operator-managed, compatibility-checked procedure. It does not fence external changes or repair drift. The startup probe allows WAL replay to complete before readiness is checked. The PVC retains `bog.wal` and `bog.commit`; follow the offline backup procedure in `docs/operations/bogctl.md`.

This is not a production replicated operator. In particular it does not implement leader election, fencing, quorum commit, sidecar replication, rolling replacement, membership changes, or mixed-version compatibility gates.
